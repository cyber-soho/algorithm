Why This Matters: Algorithmic Complexity

Before diving into specific algorithms, we must understand how we measure them. This section introduces "Big-O" notation, the standard method for describing how an algorithm's speed changes as the amount of data grows. Understanding this is crucial because algorithms aren't just abstract theory—they power search engines, GPS routing, and file compression. The chart below visualizes why choosing the right algorithm matters when dealing with massive datasets.

O(1) & O(log n)

O(1) is constant time; the work doesn't change regardless of data size. O(log n) grows incredibly slowly. If the list doubles, you only need one more step. Binary Search operates here.

O(n) & O(n²)

O(n) is linear; doubling the list roughly doubles the work (Sequential Search). O(n²) scales poorly, multiplying work exponentially (e.g., Bubble Sort).

Weapon 1: Sequential Search

This section explores Sequential (or Linear) Search. It is the simplest search algorithm, akin to looking for keys in a messy drawer. It works on any list by checking items one by one until the target is found. Use the interactive tool below to see how it painstakingly walks through an unsorted array to find a target value.

Characteristics

  • No prerequisites on the data (works unsorted).
  • Average & Worst case: O(n).
  • Stops the moment it finds the target.

When to use it

  • Small lists (under ~30 items).
  • Unsorted data where sorting costs too much.
  • Searching linked lists.

Weapon 2: Binary Search

Here we examine Binary Search, the "dictionary trick." This algorithm is massively faster than Sequential Search but comes with a strict golden rule: the data MUST be sorted first. The Golden Rule

The data must be sorted before Binary Search runs. If unsorted, it silently fails and returns wrong answers without warning.

Weapon 3: Greedy Strategy

The Greedy Algorithm is a mindset, not a fixed recipe. At every step, it takes the best option available right now, with no backtracking. While incredibly fast and useful for things like GPS routing and file compression, it isn't always perfect.
